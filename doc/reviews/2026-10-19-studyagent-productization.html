01

结论与产品定位

建议保留 Next.js + NestJS + 共享题目契约，把 StudyAgent 改造为“试卷与错题驱动的家庭学习工作台”。 当前工程已经具备学习流程骨架，现有逆向项目提供了真实试卷、图像处理和资料管理经验；最值得补齐的是内容可用性、学习结果可信度和长期使用的可靠性。

推荐的核心体验是：家长找到或导入一份可用试卷 → 整理、阅读或打印 → 孩子作答与订正 → 自动形成错题和复习任务 → 家长知道下一步怎么帮助。 教材知识体系为这条流程提供定位与诊断，助教为具体题目和学习证据提供解释。

暂按家长管理、孩子在平板上学习的家庭产品评估；这是本次建议的工作假设，不是用户已经选定的商业形态。个人内网版可简化运营与付费设施，机构版则需要另补组织、教师、班级与作业分发权限。

产品化应先交付一个完整、稳定、可恢复的使用场景，再扩到更多学科和能力。首个纵切建议选择小学数学、一个教材版本和一个年级；三年级是有现成内容支撑的候选，不代表已经决定只支持三年级。

4.2 小学数学：有答案，但缺少可直接消费的解析与选项结构

本次遍历 9,199 条小学数学试卷记录的已返回顶层题目，累计 221,305 次题目出现。这里没有跨卷去重，也没有把缺失位置计为已取得题目。

  • 221,299 次有非空题面字段，221,170 次有非空答案字段；存在 6 次空题面、135 次空答案。
  • 独立 details 解析字段非空数为 0，独立 options 选项字段非空数也为 0。选项可能包含在原题面 HTML 或图片中，需要解析，不能将字段为空解释成题目没有选项。
  • 出现 13 个来源题型；填空 94,156 次、选择 47,935 次、应用 39,798 次、计算 14,285 次、解答 11,969 次、判断 7,289 次、操作 5,187 次，其余为连线、多选、口算等。
  • 60,367 次题面包含图片标签，5,269 次包含表格，另有 MathML 和注音标签。图片与表格渲染是主链路要求。

这些数字衡量字段存在和形式特征，不能证明题目正确、图片齐全或能够自动判分。大量内容可以先提供原卷阅读和打印；选项、空位、评分协议完成审核后，再进入在线作答。

06

目标产品：三个使用面，一条真实闭环

6.1 学生端：打开就知道做什么

首页以“继续上次任务”和“今天 10–15 分钟”为主，保留错题复习和学习地图入口。进入任务前明确题数、预计时间和可用输入方式；第一次不强制做长评估，允许从家长选定试卷开始。

答题页把题面、输入、草稿区、提示和保存状态放在稳定位置。选择题可点选，填空逐空输入，数学提供常用符号与分数键盘；手写可以先保留图片和笔迹，再进入识别/复核，不将识别失败算答错。学生界面不展示 formula_blank 等内部模式名。

每题支持保存后离开、恢复、修改和清楚的提交反馈。考试模式提交后统一显示答案；训练模式按策略反馈。分步提示先给思路，再给关键步骤，完整解答的开放时机由学习场景决定。

反馈奖励完成、订正和独立掌握。重试、看答案后的作答和依赖提示的成功分开记录，不把刷提交次数当掌握度。下一步只给一个明确动作，例如“复习这两道错题”。

6.2 家长端：低成本安排与理解

主要入口为“今日安排、试卷资料、错题复习、学习报告”。首次配置学生、年级和教材版本后，系统记住常用条件；多孩子通过显式切换保持隔离。

试卷详情同时提供原卷、适用范围、题目/答案取得状态、预览与允许的操作。完整可作答卷可安排练习；只有原 PDF 的材料可阅读/打印；部分缺题材料提供明确说明及可用部分，不能默认作为完整考试。

报告优先回答：本周完成了什么、哪两个知识点有足够证据需要帮助、建议再花多少时间。展示样本题和比较窗口，证据不足显示待观察；避免由一次错误得出能力标签。

6.3 内容运营端：围绕待处理事项组织

将当前长页拆为“资源入库、待审核、试卷编排、题目编辑、质量异常、发布版本”。导入审核采用原页与结构化结果对照，能直接定位原页、题号、选项、空位和缺失图片。

审核任务按异常排队：缺题、缺答案、图像失败、选项未解析、题型未支持、学科年级冲突、许可未核实。审核记录保留修改差异、处理人和版本；批量操作先展示影响范围，并可回滚发布版本。

6.4 首个端到端使用示例

家长筛选三年级数学 → 打开已审核试卷 → 选择 8 道适合孩子的题或打印原卷 → 孩子完成并保存 → 客观题规则判分、主观题进入待复核 → 错题保留题目版本和原作答 → 依独立作答证据安排延后复习 → 家长看到具体进步与一项建议。

拍照路径复用同一闭环：相册/拍照 → 多页排序与裁剪 → 保留原图、处理图 → OCR/框题确认 → 选择仅存档打印或进入结构化作答。去笔迹、去印刷答案、OCR 和判题是四种不同能力，分别验收。

7.2 完整性决定可以做什么

内容状态允许的典型用途开放在线练习前的附加条件
只有目录/封面搜索索引、说明、回到合法来源不提供不存在的正文或下载
仅有预览明确标识的预览不包装成完整原卷
原 PDF 已验证可读阅读、允许范围内下载/打印完成切题、选项/空位、答案协议和审核
结构化题面存在但缺题阅读已有内容、显式选取可用单题不作为完整考试；不能通过去掉缺失位置提高原卷完整率
结构题目齐全整卷阅读、候选练习答案、媒体、题型、元数据、使用范围和审核继续分别通过
已审核的可作答资产对应支持题型的在线训练/评估固定版本、判题协议和设备支持范围

可用性建议从独立维度计算：content / answers / explanations / media / metadata / rights / review / interaction。例如“题面齐全但无解析”可以提供受控客观练习；“只有答案图片”先进入答案查看/人工复核模式。AI 生成解释单独保存为派生内容，标明模型、依据、版本与审核状态。

7.3 入库流程与质量门禁

  1. 扫描已保存来源，生成只读盘点和候选清单，识别精确身份、完整性及许可范围。
  2. 建立媒体清单，验证路径/摘要/可解码状态，并将原图和原 PDF 保存至私有对象存储。
  3. 来源适配器把 HTML、PDF 或图片转换为统一块；保留注音、公式、表格、共享阅读材料、原页和边界框。
  4. 题型映射、选项/空位提取、答案规范化及教材知识点候选分别产生质量标记；不能仅凭标题自动确定教材版本。
  5. 人工在原页对照台复核；未知字段保留未知。生成题与原卷缺失内容分开存储，不冒用来源题目身份。
  6. 发布服务统一检查必要题面、完整媒体、答案协议、支持题型、知识点依据及使用范围。首次发布冻结内容版本。
  7. 评估/训练引用冻结版本；内容修订不会静默改变历史作答、评分和导出结果。题目撤回后保留历史依据，并能重算受影响报告。

对接首批小学数学时，优先处理选择/判断、可明确评分的数值填空和公式题；应用题、操作题、连线题先支持原题阅读和人工复核，再逐步开放自动评分。

导入按批次和来源版本推进，保留检查点与错误队列，先发布经审核的选定范围。目录可先建立完整索引，题目正文和大文件按采用范围接入；不把整库 JSON 直接装入当前内存存储。搜索与列表使用服务端分页，默认返回摘要和可用操作，题文按需读取。

08

技术改造路线

8.1 保留主体，补齐可靠性边界

  • Web 保留 Next.js，逐步形成平板/手机自适应的 PWA。家长、学生、内容运营分别组织导航；离线缓存按账号、学生和资源版本隔离。
  • API 保留 NestJS，以账户、内容资产、学习记录、复习、报告和 AI 为模块边界。认证从服务端会话恢复，令牌有失效/撤销；跨域使用受控来源和明确的 Cookie/CSRF 或令牌方案。
  • PostgreSQL 作为业务真值，Prisma 通过仓储接入。补齐当前 schema 缺少的监护绑定、教材结构、题目关系、作答/结果、计划、消息、导出和审计等实体，并添加外键、唯一约束、索引和迁移。
  • 搜索先使用数据库索引和经过实测的中文检索方案，保留可替换查询接口；按年级、学科、教材、来源与可用性组合查询，服务端限制页大小。达到真实瓶颈后再决定独立搜索服务。
  • 私有对象存储保存原件、派生文件和导出；数据库只保存已登记引用。先验证写入再登记完成，定期清理孤儿派生文件，原始资产按保留策略管理。
  • 单独 Worker 执行导入、OCR、图像处理、PDF、AI 解释和报告。初期可用 PostgreSQL 任务表与租约，吞吐确有需要时再引入 Redis/BullMQ；避免同时维护两套任务真值。
  • 业务变更与 Outbox 事件在同一事务提交；消费者幂等。导出、作答和复习调度均使用可重放的任务/请求身份，明确“至少一次传递”的去重责任。
  • 图像/模型能力通过独立服务接口接入，记录算法、模型、参数及输入输出摘要；来源项目的通过记录不直接放行新运行环境。

8.2 关键接口与事件建议

建议接口包括 POST /uploads、POST /imports、GET /jobs/:id、GET /papers、GET /papers/:id、POST /papers/:id/exports、POST /practice-sessions、PUT /practice-sessions/:id/items/:itemId/response、GET /reviews/due。

上传采用受控对象身份，不接受用户提交任意服务器路径。导入/导出先返回任务 ID；页级任务可以续跑，用户能看到已完成页、失败原因、重试和取消。完整性与文件生成成功分开记录。

提交响应携带 Idempotency-Key、题目版本和客户端修订号。区分自动保存草稿与最终提交；冲突时保留两份草稿并提示选择。学生时区用于“今日”与复习到期，服务器保存 UTC 时间，避免跨设备日期不一致。

事件示例为 content.published、practice.item_submitted、grading.completed、mistake.recorded、review.completed、export.completed。事件记录版本、所有者和幂等身份；报告只消费已确认的学习记录。

8.3 AI 的职责

优先提供当前题的分步提示、错因解释和家长建议。标准答案来自已审核资产或明确的判题规则；主观题使用评分量规、置信度和待复核状态，人工改判可追踪。

聊天以授权上下文为输入，必要时检索已审核本地材料；实时外部搜索作为独立可选工具。生产服务不依赖每次启动桌面 CLI。加入任务级超时、预算、限流、取消和熔断；模型不可用时仍可保存作答、规则判分、看原卷、打印和复习，尚未评分的内容显示待处理。
