## 1. 本轮目标

以 **StudyAgent 学习工作台** 作为登录后的唯一产品载体。课程、助教、学习安排、知识诊断、学习报告、资料、日历及档案管理都在同一套工作台中访问。

继承现有工作台的导航、字体、颜色、页面密度、列表、标签、弹窗、抽屉与课堂交互；将观察室能力拆到合适的位置，并按工作台规范整理页面正文。原有课程、诊断、计划、作答、授权及恢复语义继续复用。

用户已要求先整合计划并本地提交，再持续完成包括本整改在内的全部剩余开发。演示交互保留为参考；实际迁移、接口、数据、交付与验收按150分批实施。

## 2. 已核实的现状与问题

### 2.1 两套产品外壳同时存在

- `components/study-nav.tsx`：观察室顶栏，包含学习首页、学习工作台、家长空间、知识诊断、今日学习、题卷资料；品牌为“学习观察室”。
- `app/studio/studio-navigation.tsx`：工作台侧栏，包含首页、课程、学习动态、历史、资料和 AI白板；品牌为“StudyAgent”。课程课堂、资料课程、白板等已有复用。
- `/learn` 与 `/studio` 都承担首页；工作台顶部仍有“学习观察室”，侧栏底部还有“返回学习首页”。登录页、全局标题也使用观察室品牌。

结果是跨一个业务流程时，品牌、导航位置、布局、文字层级及返回逻辑会改变。“返回学习首页”还会把用户带出工作台。

### 2.2 观察室页面承担了多个职责

- `/parent/dashboard` 同时包含孩子档案、学习概况、知识证据、指导、复测、周报、学习记忆和助教。
- `/student/assessment` 同时包含范围、测评、报告、原因验证、指导计划和复盘。
- `/student/today` 同时包含今日安排、指导训练、错题和到期复测。
- 工作台资料页主要是 PDF 页级处理与个性化学案，`/library` 另有题卷资源与选题练习。

仅向侧栏添加这些旧页面的链接，会继续保留重复职责与两种正文风格。需要按用户任务拆分，再复用既有业务组件。

### 2.3 上下文与路由存在兼容差异

- 观察室使用 `studentId`；部分工作台地址仍使用 `student`。
- 工作台还使用 `courseScope=adult`、`audience`、课程/讲座/助教定位、筛选与学习模式参数，不能只保留学生和学科两个参数。
- `student/knowledge` 当前会转到家长页；它不能直接作为未来学生报告入口。
- 当前工作台资料页依赖 `overview.selected`；无孩子的成人会被引导建档。统一外壳时必须明确成人资料的真实能力和限制。
- 家长、学生、教师、管理员的权限不同，菜单统一不等于操作权限相同。

## 3. 信息架构：保留六个入口，补三个学习入口

推荐采用 **单层菜单、轻分组、页内标签**。一级入口不展开成多层树；一级负责用户目标，二级标签负责同目标下的业务状态。

```text

  课程
  学习任务       新增

学习观察

  学习报告       新增
  学习动态       保留，内容为日历与安排

  资料
  AI白板

  学习档案       家长、获授权管理者
  教研与管理     按当前角色和具体授权显示
```

原六个菜单名称和图标风格保留，只调整到分组中的位置。新增三个一级入口；“家长空间”拆入上述功能区。“学习观察”成为功能分组名称，不再另设产品首页。

“学习动态”保留现名称，页面标题下补“日历与学习安排”，与报告和历史明确区分。后续若实测仍易混淆，可独立调整名称为“学习日历”。

### 4.1 首页的取舍

工作台首页继续保留现有两种模式及输入、工具、模型选择、课程创建交互。将 `/learn` 已有“一个主要下一步”能力以紧凑的继续学习区融入页面，不把旧观察室的大标题、统计面板和长篇说明整体搬入。

家长看到“待确认计划 / 查看学习安排”；学生看到“继续作答 / 今日任务”；成人看到自己的课程或助教断点。无任务时显示能执行的课程或帮助入口，不制造评测结果。

首页读取仅取回已有状态；卡片、菜单、页签及浏览器返回均不自动生成课程、开始测评或产生作答。

### 4.2 诊断、报告、计划如何分开

职责划分为“诊断中作答、报告中解释、任务中执行、日历中安排”。

报告详情继续引用原测评会话和冻结版本；在报告选择“制定/查看指导计划”后打开任务区的同一计划。计划保存来源报告与返回位置；“返回报告”定位原会话。既有报告中的计划面板通过提取组件过渡，不建立第二份计划记录。

诊断完成进入 `/studio/reports` 下的原会话详情。学生报告只显示适合其身份的事实、解释和下一步；监护决定、管理、复核仍按现有权限提供。

### 4.3 资料如何合并

保留当前 PDF 和个性化学案组件，引入题卷资源子页。各页签拥有自己的检索条件、分页、授权和来源完整度。

成人个人资料与孩子授权资料明确分开。在成人持久资料链路尚不满足时，展示准确限制和可用课程来源入口；不强制创建孩子，不通过空学生 ID 绕过现有接口。

## 5. 视觉与交互继承规范

### 5.1 直接继承的基础

以当前 `studio-navigation.tsx`、`reference-navigation.generated.css`、`reference-navigation.css`、`workspace.css`、`workspace-dialog.tsx` 为源，提炼共享外壳及组件。

- 侧栏展开宽度 240px，收起宽度 60px；现有 1000px 窄屏断点、抽屉开关和用户级收起偏好继续使用。
- 白色侧栏、浅灰工作区、灰色线性图标、柔和浅蓝选中态。现行侧栏选中背景 `#E8F0F8`、文字 `#4C6696`，以源码定义为准。
- 沿用本地 Satoshi / MiSans 字体和现有字号层级；侧栏约 13px、图标 20px、线宽 1.5。教学白板的专用字体继续按课堂规则加载。
- 桌面菜单保持现有约 33px 的紧凑行高；触屏有效点击区域至少 44px。页面正文的操作和状态沿用课程、资料页的控件规范。
- 标签、列表行、按钮、选择器、弹窗、抽屉和提示使用共享组件及工作台 token，减少各页面私有 CSS。
- 继续学习和近期活动保留为折叠区域；较矮屏幕优先保证主菜单和底部入口可达。

### 5.2 必须调整的旧视觉

观察室正文中的大段宣言、衬线/手写式强调标题、独立左侧叙述栏和大面积装饰，收敛为工作台的标题、工具行、列表和按需详情。

知识、原因与报告中的有用说明保留，但按“结论 → 依据 → 详情”组织。概览只展示最有助于行动的内容，完整证据可展开，不删除已有事实和不确定性。

打印、原卷、公式、课堂白板与全屏播放使用专门内容布局，不被通用卡片、全局排版和侧栏宽度强制缩放。

### 5.3 全局和局部交互

- 左侧：当前功能位置；顶部：当前学习对象、适用学科和当前位置；正文：本页筛选、标签与动作。
- 切换对象保留当前功能类别，清除旧对象投影后读取新数据；不得因迟到响应显示另一孩子的报告或草稿。
- 二级页签支持 URL、刷新和浏览器前后退；详情返回恢复原筛选、分页、滚动和选择。
- 课程、课堂与练习进入专注布局时仍属于工作台。侧栏可收起，返回定位原课程/单元/题目/句子。
- 退出、跨对象切换或关闭编辑器时，使用既有草稿/未保存提醒；不为每一次普通菜单点击增加确认框。
- 全局助教按页面和活动绑定上下文，复用已有持久对话。课堂内嵌助教继续保留；同一屏避免叠放多个助教入口。

## 6. 学习对象、身份和权限

### 6.1 一个明确的当前学习对象

家长可选择“我自己 · 独立学习”或已有授权孩子。学生绑定其学习码对应档案；教师与管理员仅按当前有效授权选择对象。

儿童对象显示学科选择；成人独立课程使用课程本身的范围，不被默认小学数学绑定，也不要求先创建孩子档案。GESP 按独立认证等级轨道处理，不伪装成普通年级学科。

方案中用 `audience: self | student` 表达明确的对象意图，作为前端设计模型；实际字段须核对现有契约后定，不预先宣称已有后端支持。

### 6.2 菜单差异

| 身份 | 主要菜单与操作 |
| --- | --- |
| 学生 | 课程、本人任务、本人诊断与报告、日历、历史、获准资料、AI白板；无家庭管理、权限管理与数据删除入口 |
| 家长查看孩子 | 完整学习菜单、档案、授权和计划确认；练习为预览或安排，不能代写孩子首答 |
| 成人独立学习 | 首页、课程、已有个人任务/日历/历史/资料/白板；儿童知识诊断与儿童报告不显示，未接通的成人能力不展示成可用按钮 |
| 教师/管理员 | 获授权学习视图及逐项管理入口；不把菜单显示范围等同于数据权限 |

成人任务页只复用已支持的个人安排；对话练习的成人持久任务和本人作答仍属于 147 的后续范围，本次改壳不算补齐。

菜单渲染以服务端已有角色、授权和能力响应为依据。隐藏入口只是展示规则；所有读取、写入、撤权、共享和媒体访问继续由后端校验。

## 7. 关键完整旅程

1. **家长初次使用**：工作台首页 → 添加学习档案 → 诊断中确认已学范围 → 查看测评预览 → 由孩子学习码完成测评 → 家长查看原报告 → 确认指导计划 → 在任务/日历执行与复盘。
2. **孩子继续学习**：登录后进入工作台首页 → 一个主要下一步 → 原课程/原题/原句继续 → 草稿和首次作答分别保存 → 返回任务或课程原位置。
3. **报告到干预**：报告中的待验证原因 → 原探针与原始证据 → 查看/制定同一指导计划 → 任务执行 → 到期独立复测 → 原报告与复盘互通。
4. **资料到课程**：资料区选择个人 PDF 或合法题卷 → 查看原页和当前处理状态 → 创建来源课程或明确选题练习 → 进入课程/练习 → 返回原资料与筛选。
5. **成人自学**：选择本人独立学习 → 保留工作台课程创建/即时帮助 → 课程/助教/白板 → 原学习记录恢复，全程不借用孩子档案。
6. **教学安排**：助教来源 → 练习预检/候选/安排 → 孩子任务 → 分组本人作答。未完成界面和成人链路继续作为 147 后续功能，整改仅为其预留正确位置。

### 8.1 建议新增的页面地址

- `/studio/tasks`：任务主区，页签与具体活动使用稳定参数。
- `/studio/assessment`：诊断主区，保留当前测评会话定位。
- `/studio/reports`：报告列表与具体报告/知识/原因/复盘定位。
- `/studio/profiles`：学习档案、授权、学习码、设备。
- `/studio/settings`：账号和数据管理。

已有课程、日历、历史、资料地址先继续兼容 `view`。用户可感知的是导航统一；不要求在首批重写全部地址。

### 8.2 深链与草稿兼容

建立显式旧参数到规范参数的适配器；核对 `student` / `studentId` 冲突时拒绝歧义，不静默选择另一个孩子。保留已验证的课程、讲座、单元、句子、题目、session、report、plan、筛选、来源与助教定位字段。

兼容规则使用白名单逐项定义，不任意透传敏感参数。浏览器 URL 不承载登录凭据。旧 return URL 只接受同站点合法路径，不能形成开放跳转。

活动内原有本地草稿键和服务端命令键维持；导航改名不得更换作答 actor、首次响应、题包、曝光和冻结快照。旧路径进入仍能恢复原活动；需要格式迁移时另列迁移及回退验证。

## 9. 技术组织建议

从工作台提取 `WorkspaceShell`、`WorkspaceNavigation`、`WorkspaceContextBar`、`WorkspacePageHeader`、`WorkspaceTabs`、`WorkspaceDialog` 等共享能力，名称为设计建议。

- 共享外壳负责身份、导航、对象、适用学科、布局模式、全局会话状态与错误恢复。
- 页面负责各自业务读取和动作；原课程、测评、报告、计划及媒体服务继续是事实来源。
- 通过 App Router layout / 路由组或等价组合，让外壳在页间保持；避免每个页面各挂一份侧栏并重复恢复身份。
- 未登录、打印、分享与管理页面有显式布局模式；登录页不强制挂学习侧栏。管理工作区仍属于同一品牌和外壳，管理子导航只在管理范围展开。
- 当前 `LearningStudio` 中的导航与业务视图逐步分离；`StudyNav` 在迁移完成前承担兼容入口，全部替换后再收敛。
- 接口优先复用 `/learning/home`、现有 overview、today、诊断、报告、计划、记忆、授权与 studio 能力。实际数据不足时明确补合同与专项，不复制一套统计或测量逻辑。

本整改以 UI、信息架构、上下文和路径兼容为主。若发现成人资料、学生报告投影等缺少真实后端能力，作为独立功能列项，不把导航接通视为功能完成。

## 10. 分批实施与退出条件

### A. 工作台统一外壳与入口

提取原有导航/字体/token/弹窗；接对象选择和账号入口；统一品牌、登录后着陆及主要下一步。选取首页、课程、任务三个代表页面核对桌面与手机。

退出条件：单一侧栏、无观察室来回跳转、URL/刷新/后退不丢对象、成人无强制建孩子、学生无管理入口。

### B. 学习功能归位与页面正文整理

依次迁移今日任务 → 诊断/报告 → 指导/复测/知识视图 → 档案授权 → 题卷资料。统一各页标题、列表、标签、状态、详情与返回；保留原业务数据和写入语义。

退出条件：家长、学生、成人三条代表旅程连续走通；原作答、计划和报告定位保持；正文风格与工作台一致。

### C. 特殊工作区与兼容收尾

统一课堂、白板、资料课程、项目、原卷/GESP专注布局及管理范围；按迁移清单核对所有入口，再启用规范地址和旧深链兼容。

退出条件：原页面无功能漏项；没有重复菜单/助教/滚动宿主；打印和播放不被全局 CSS 破坏；旧草稿与旧活动可恢复。

### D. 完整回归与交付

在主目录 `data/qa/` 内使用隔离库、端口和构建验证。保存首次失败、复验、截图和内容/数据前后核对。最后核对实际运行版本、身份、入口及回退材料，按用户授权进行提交/推送/发布。

退出条件：改造对应的需求、功能、路由、浏览器与双库证据可以互相追溯。通过导航整改不提升教材质量、真实设备或长期学习效果的完成状态。
