# 报告核对请求去重与指导闭环

2026-10-21 的完整浏览器旅程把能力评测继续推进到指导计划。测试从建档、年级知识点、题组预览、11 题作答和证据报告，继续生成规则指导计划、家长确认启动，并验证 D+1 与 D+14 复测已经排期。

这一流程发现报告页会重复挂载“核对报告依据”组件。Playwright trace 记录同一 `analysis-status` 在约一秒内被请求 1,136 次，最终触发用户限流，指导按钮持续禁用。服务返回本身一直正确，问题在于组件重挂载后没有共享请求结果。

修复把核对结果缓存提升到模块级，以 `sessionId / reportVersion / retry` 为签名共享一个 Promise、成功结果或错误。组件重新挂载时直接复用结果，不再重复请求；真正切换报告或用户主动点击“重新核对”仍使用新签名。浏览器测试同时统计网络请求，断言该流程最多发起 1 次 `analysis-status`。

E2E 启动器还显式清空 `OPENAI_API_KEY` 与 `CODEX_MODEL`，让 CI 验证无模型时仍可完成的确定性计划和复测排期，避免本机密钥或外部网络决定结果。

最终生产构建下三条 Chromium 旅程 3/3 通过、0 失败、0 flaky，总用时 16.66 秒。收据见 [浏览器验收](../evidence/2026-10-21/browser-product-acceptance-local.json)。该结果证明离线降级和界面链路可用，不证明在线模型质量、真实教师指导效果或间隔学习效度。
