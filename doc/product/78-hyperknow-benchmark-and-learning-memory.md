# Hyperknow 拆解与证据化学习记忆

2026-10-21 先对 `https://agent.hyperknow.io/` 做了未登录公开产品审阅；用户在单独授权并自行完成登录后，又对普通界面做了可观察审阅。没有读取 Cookie、本地存储、令牌或私有接口，也没有加入课程、购买或批量导出内容。公开包结论和登录后界面结论分别归档，版本快照与哈希见 [公开产品证据](../evidence/2026-10-21/hyperknow-public-product-evidence.json)，登录后观察见 [授权界面证据](../evidence/2026-10-21/hyperknow-authenticated-ui-evidence.json)。

## Hyperknow 的产品做法

Hyperknow 的核心不是单一聊天框，而是围绕学习任务组织的一组连续入口：Courses、Learning Feed、History 和 Marketplace。公开包显示它可以生成课程、Deep Learn Session、白板讲解、练习、单元考试、闪卡和测验；课程又有 units、lectures、sessions、practice、unit exam 和 project stages 等层级。

来源和生成内容联系得比较紧。知识库支持上传 PDF、Word、PowerPoint、Excel、Markdown 和文本，也能从 Canvas 选择课程文件。Agent 可以生成带页级引用的回答，点击引用预览原页；课件和辅导可以转成白板讲解或 PDF 页级 walkthrough。它的优势是“我的资料 → 结构化课程 → 当次讲解 → 练习与考试 → 下一次 Feed”的连续体验。

登录后的可视化实测进一步说明了这种连续体验如何被用户感知。在一个普通分数加法请求中，界面依次暴露 `Loading skills`、`conceptExplanation`、`Recalling Memory` 和 `Visualizing Fraction Addition`；记忆检索会明确显示“没有相关记忆”，不会把空白伪装成有依据。文字解释先出现，图形稍后生成，随后补齐分数条、通分算式和三条要点。回答底部还给出减法和最小公倍数等下一问，输入区保留语音、工具、语言和响应速度控制。这种“知道系统正在做什么、先得到可读内容、再等待视觉素材”的节奏很适合产品级讲解。界面本身不证明内容正确或学习有效；可视化是否准确仍需来源、教研和测量闭环验证。

Learning Feed 是日历式界面，已有今日待办、完成项、已确认与待确认任务、批量删除和周期额度等入口。本次账号为空，无法观察推荐排序依据，因此不推断其算法。课程预览在全屏大纲中显示五个单元、 lectures、每个 session 的 Learn/Practice、项目与单元考试，同时展示 Not started、Attempted、Familiar、Proficient、Mastered。未加入课程时打开练习会出现确认框，并要求选择不可在加入后更改的课程语言；本次没有确认加入，避免改变账号状态。可迁移的是“先看完整蓝图，再决定加入”和“学习、练习、项目、考试同一导航”；不可直接采用的是完成动作直接驱动掌握标签、生成后直接公开和市场内容复制。

它还有主动学习层。公开文案和接口名称显示 Learning Feed 会汇总课程下一步、练习、临近任务和推荐内容；Canvas 可同步课程、作业、截止日期和公告，Google Calendar 可接收日程。这减少了用户每次从零描述目标与材料的成本。

记忆是另一项关键设计。设置中存在会话记忆开关、结构化学习进度与偏好、个人记忆管理和可编辑的外部记忆；外部记忆可由用户从其他 Agent 复制后导入，也可以单独清空。这个方向值得借鉴，尤其是“跨会话继续”和“用户可检查、可删除”。

课程进度使用 Attempted、Familiar、Proficient、Mastered 四级。公开文案把 Familiar 绑定到完成课程、Proficient 绑定到练习至少一半正确、Mastered 绑定到练习全对。这套反馈很适合快速导航，但完成动作和一次练习分数不能直接当作稳定掌握，这也是 StudyAgent 不能照搬的地方。

## 与 StudyAgent 的差异

| 维度 | Hyperknow 的强项 | StudyAgent 已有基础 | 应吸收的部分 |
| --- | --- | --- | --- |
| 学习入口 | 课程、Feed、历史、市场一体化 | 家长空间、知识诊断、今日学习、题卷库 | 把待办、未知点、计划和复测组织成“一个下一步” |
| 资料使用 | 家庭知识库、Canvas、页级引用 | 完整教材内审源、题卷库、来源和媒体指纹 | 后续建设家庭资料来源与页级证据定位 |
| 学习组织 | 自动生成课程蓝图、单元、讲次 | 258 原子点、先修图、教师审核和版本冻结 | 保留结构化路径，禁止生成即发布 |
| 能力测量 | 快速、连续、易理解 | 题族、维度、区间、基础/迁移、间隔复测 | 继续以证据链为核心，不用完成率替代测量 |
| 记忆 | 可管理、可导入、可清空 | 已有范围、报告、假设、计划和复测记录 | 形成可核对的记忆快照，不让模型自由编造人格标签 |
| 教学呈现 | 白板、旁白、页级讲读 | 教学卡、例题、结构化题目、助教 | 后续评估安全白板与逐步讲解 |
| 连接器 | Canvas/日历主动同步 | 本地 API、持久任务和权限边界 | 在明确监护授权后建设学校/日历连接器 |
| 运营 | 分享、发布、市场、更新流 | 教师审核、覆盖看板、版本历史 | 可借鉴可发现性，但不能自动公开未审内容 |

Hyperknow 更像“把资料转成学习体验的 Agent 工作台”；StudyAgent 更像“对小学知识能力做可复核测量的学习诊所”。我们应当吸收它的连续性和来源感，同时保留更严格的测量与儿童隐私边界。

## 本次整合

本次新增 `GET /api/learning/students/:id/memory?subject=...`。它实时生成可核对的学习记忆，不存储开放文本人格设定，也不让模型凭空写“孩子粗心”等标签。

记忆内容分为：

- 已确认事实：当前年级、学期、教材范围、已学点、指导计划、最近评测和复测安排，带学习范围或计划/会话来源标识。
- 仍保持未知：没有独立有效证据或样本不足的知识点；未知不显示为薄弱。
- 待验证解释：现有规则诊断产生的原因假设、观察、解释和下一步。
- 主动学习 Feed：到期复测、待确认计划、未完成评测、今日计划和证据缺口，按教育优先级排序。

接口要求当前监护人、教师或获授权学生身份；越权访问返回 403。家长空间新增“证据化学习记忆”卡片，首屏直接显示事实、未知和下一步；“记忆边界”明确说明来源、生成方式与不包含的内容。AI 助教的上下文也加入同一类事实、未知、假设和待复测信息，并在无模型 key 时用确定性文本继续回答。

这样吸收的是 Hyperknow 最有价值的两点：跨会话连续性和基础来源上下文。我们没有接入它采用的外部记忆粘贴方式，因为未经审核的第三方文本和自动记忆会把不可信内容带入儿童指导；也没有把课程完成率、练习得分或白板观看完成当成掌握。

随后，计划活动开始冻结教材来源引用。生成计划时，系统根据确认范围内的教材、已审核课时映射快照和知识点找到对应章节、课时与候选页码；引用随计划版本保存。页码仍标为“待教研逐页确认”，因为当前候选文件不等于人工校验结果。家庭界面显示来源、版本和位置，但不直接开放受版权限制的整本原卷。这样既能让学生知道自己学的是哪一课时，也不会把来源匹配或候选页码夸大成已核验事实。

验证结果：学习记忆与越权边界、助教上下文共 34 项定向测试通过；全仓 155 个文件、706 项中 700 通过、0 失败、6 项 PostgreSQL 默认跳过；生产构建浏览器旅程 4/4 通过，并完成“建档 → 评测 → 报告 → 计划 → 复测排期 → 重新打开家长空间读取已更新记忆”的连续旅程。桌面视觉复查修正了浮动助教遮挡记忆印章的问题。运行收据见 [学习记忆回归](../evidence/2026-10-21/hyperknow-learning-memory-runtime.json)。

## 后续优先级

1. **P0，已完成**：证据化学习记忆和主动 Feed。
2. **P1，部分完成**：计划活动已带教材、章节、课时和候选页码引用，并保留“待人工逐页确认”状态。家庭自主上传知识库仍需先定义监护人授权、文件生命周期、恶意文档隔离和删除语义，再接入解析与引用预览。
3. **P1**：按教材实际课时生成可审核的学习路径。现有教材、课时候选和教师门禁已经就绪，下一步是提高页级定位质量，仍由人员批准发布。
4. **P2，已开始**：白板或图形逐步讲解。首批在已审核教学卡上增加结构化分数条，覆盖分数等值、异分母加法和减法；渲染器只消费受限 schema，不把自由生成 SVG/HTML 送进学生页面。图形依次展示同一整体、统一分数单位和数份数，并明确“看过图不等于掌握”，后续用不同数值新题和延迟复测验证。
5. **P2**：学校 LMS/日历连接器。只有在租户隔离、OAuth 撤销、监护同意和最小权限明确后实施；国内家校日历应先做本地导入。
6. **暂不采用**：不透明人格记忆、自动从聊天写长期标签、完成即掌握、生成即进入市场。
