# 存储读取性能与快照隔离交付

2026-10-20，接续 `28f52d2`。覆盖OPS-01/02及M10性能基线的一部分，未改变测量或评分语义。

## 实现与一致性

领域数据库为当前版本维护深度冻结的只读快照。每次请求仍在数据库事务中读取版本；版本相同才复用快照，其他进程或worker写入后，下一次请求重新读取对应版本。PostgreSQL使用一致的可重复读事务，SQLite使用同一读事务，避免版本和记录来自不同时刻。

请求工作区只在首次访问某个集合时克隆该集合。未访问的题目、报告或作答记录共享只读基线，不能跨请求修改。提交差异跳过仍共享同一不可变引用的集合；成功事务只更新缓存内发生变化的记录及顺序。失败事务不更新缓存，公开维护接口仍返回独立可变副本。多次提交的工作区保留正确检查点。

版本冲突仍返回409，保留原有全域版本检查；没有自动重放业务代码，也没有只验证写入行而遗漏授权、计划状态等读取依赖。缓存不会把旧授权写入变成成功。进程内诊断计数记录版本读取、整库载入、缓存命中、提交、冲突和克隆量，不含学生内容或账号令牌。

## 实测

同机Node24、SQLite，1,000个合成家庭、20,000条合成作答，加现有3,435道原创任务，数据库约52MB。使用隔离临时库与真实Nest HTTP处理；验证家庭列表仅返回当前家庭。每个顺序接口12个样本，并发身份查询为8并发、4轮。两次运行均有后台资产备份，结果是本机样本，不能外推生产容量。

- 身份查询p95：908.50ms → 3.97ms。
- 家庭列表p95：839.48ms → 22.39ms。
- 课程目录p95：796.08ms → 7.79ms。
- 8并发身份查询p95：6,217.43ms → 10.17ms。
- 采样结束进程RSS：约1.95GB → 0.37GB；不是全生命周期峰值或容量保证。

可重跑 `node scripts/qa/verify-storage-performance.cjs <标签> <证据路径>`。脚本仅创建和删除自有临时数据库，输出合成数据规模、硬件、样本、事件循环与内存。前后记录分别为 [基线](../evidence/2026-10-20/storage-performance-before.json)、[优化后](../evidence/2026-10-20/storage-performance-after.json)。

## 回归与剩余工作

新增4项快照/工作区回归，覆盖只读缓存和可变副本隔离、顺序更新和删除、其他连接撤销权限、失败唯一写入不污染缓存、失败请求和多次提交。针对存储/任务/重启/媒体竞态17项通过；最终全量124项通过，4项PG默认跳过。PostgreSQL17另行4项实机通过，增加跨连接缓存失效断言，见 [PG运行证据](../evidence/2026-10-20/postgres-snapshot-runtime.json)。全仓类型检查与API构建通过；Web未改动。

该阶段解决重复载入和无关集合复制。冷启动、其他进程提交后的首次读取仍加载整个领域库；访问集合仍整体克隆；全域版本使无关写入也可能冲突。需要继续设计带读取依赖的按聚合查询/事务、并发写入与更大数据规模验证。原始大题卷始终使用独立索引库。本地读取样本达标不能视为M10或产品总目标完成。
