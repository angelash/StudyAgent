## 2. 用户确定的方向与六项决定

方向（用户原话要点）：

- 充分学习 HyperKnow：课程管理、课程生成、白板讲授、语音与字幕、大模型实时答疑。
- 原有核心是完整教学闭环：资料收集 → 能力评估 → 针对性课程设计 → 教学后质量验证。两者互补，要有机整合。
- 以 HyperKnow 的 Web 交互样式为主，重新设计整个平台。
- HyperKnow 镜像资源自用，授权问题不处理。
- 面向所有人，不按人群分产品形态，只分课程区。

六项决定（用户接受的默认方案）：

1. 闭环覆盖 AI 生成课程，证据分两级：已审核知识点是正式证据；AI 课程按课程目标记录，标注「估计」。两级不合并成一个掌握度数字。
2. 注册改为邀请制。属于权限改动，发布前需用户当次确认。
3. 界面统一称「学习者」，可选「陪伴者」查看他人档案；底层 parent/student 角色暂不改。每个档案有「未成年」开关，打开后 AI 输出检查更严格。
4. 保留 API 和测量引擎，在现有 Web 应用内逐页重建，不另起前端。
5. 外壳完成前内容编写继续冻结；「真实教师/真实设备验收」改为用户本人走查。
6. 首批端到端样板两门：一门 AI 主题课程（估计级），一门小学数学教材同步课程（正式级）。

## 3. 产品模型

### 3.1 课程是中心对象

学习者在平台上做的每件事都属于某一门课程，或属于跨课程的「学习档案」。闭环的五个阶段不再是五个并列的顶层入口，而是每门课程内部的五个页签：

| 阶段 | 学习者看到的 | 对应用户的原始闭环 |
| --- | --- | --- |
| 资料 | 这门课用到的教材页、上传文件、检索摘要，可回到原页 | 资料收集 |
| 摸底 | 开课前的短评测及其结果，决定从哪里讲起 | 能力评估 |
| 单元 | 课程蓝图、单元与课时、白板课堂、字幕语音、实时答疑 | 针对性课程设计与讲授 |
| 练习 | 随堂题、单元练习、错题与笔记 | 讲授的一部分 |
| 验证 | 单元核查、到期复测、前后对比报告 | 教学后质量验证 |

### 3.2 课程区

课程区决定内容来源和证据等级，不决定界面。所有课程用同一套外壳、同一套课堂。

| 课程区 | 内容来源 | 证据等级 | 现有实现 |
| --- | --- | --- | --- |
| 教材同步 | 已审核的原子知识点和题目 | 正式 | `studioCourses`；初中化学是完整模板（课程 + 课前诊断 + 单元核查 + 复测） |
| AI 主题 | 检索摘要 + 模型生成，蓝图经学习者确认 | 估计 | `courseCraftRuns` → `sourceCourses`（`craft` 字段） |
| 我的资料 | 学习者上传的 PDF、文本 | 估计 | `sourceCourses` |
| 认证备考 | GESP 等独立轨道 | 正式（已审核部分） | GESP 模块；生产环境默认关闭学生代码运行 |

### 3.3 两级证据

测量引擎的三条规则不变：没有证据显示「未知」而不是「薄弱」；AI 不能直接写掌握度；复测按 1/3/7/14 天。

| | 正式证据 | 估计 |
| --- | --- | --- |
| 产生于 | 评测、单元核查、复测（`diagnosticResponses`） | 课堂随堂题首次作答（`classroomSessions[].answers`） |
| 粒度 | 原子知识点 | 课时目标（每课时一个 `objective`） |
| 计算 | Beta 后验、95% 区间、理解/执行/迁移/保持四维 | 首次作答的正确数与作答数，按提示等级折算；作答不足 3 题显示「证据不足」 |
| 展示 | 未知 / 证据不足 / 学习中 / 不稳固 / 稳固 | 一律带「估计」字样：未作答 / 证据不足 / 估计需巩固 / 估计已达成 |
| 进入学习档案 | 进入知识点掌握图 | 单独一栏「课程目标（估计）」，不进入掌握图 |

两级永不合并：任何页面都不把估计结果折算成知识点掌握度，也不把两者加总成一个百分比。`formalMeasurementEligible` 在资料课程和 AI 课程上保持字面量 `false`。

第一版的估计级做成**读取投影**：从已有的课堂作答记录按课时目标汇总，不新增集合，不升 schema。是否另存快照留到样板课程走查之后再定，那是持久化改动，需要单独确认。

## 4. 信息架构

### 4.1 侧边栏：九项收为五项

| 新入口 | 路径 | 说明 |
| --- | --- | --- |
| 首页 | `/studio?view=home` | 一句话创建课程、继续学习、今天要做的事（到期复测、未完成课时） |
| 课程 | `/studio?view=courses` | 课程库，按课程区筛选；打开后进入课程内页签 |
| 资料 | `/studio?view=materials` | 跨课程的资料库 |
| 日历 | `/studio?view=calendar` | 原「学习动态」，改名 |
| 历史 | `/studio?view=history` | 对话、课堂断点、白板讲解 |

侧边栏底部保留三项：学习档案（跨课程，`/studio/profiles`）、账号与设置、教研与管理（仅教师和管理员）。侧边栏的无障碍名称 `学习工作台导航` 不改，十个浏览器用例靠它定位。

被收拢的四项：

| 原入口 | 去向 | 旧路径 |
| --- | --- | --- |
| 学习任务 | 首页「今天要做的事」+ 课程内「练习」「验证」页签 | `/studio/tasks` 作为深链接保留到第 8 块 |
| 知识诊断 | 课程内「摸底」页签；跨课程入口在学习档案 | `/studio/assessment` 同上 |
| 学习报告 | 课程内「验证」页签；跨课程汇总在学习档案 | `/studio/reports` 同上 |
| AI 白板 | 首页创建入口；已生成的白板列在历史 | `/studio/whiteboards` 同上 |

### 4.2 课程内页签

现状：打开课程后左侧有 `.cl-course-tabs` 页签条，内容是「单元 / 资料 / 练习」，化学课程多一个「考核」。页签状态走 `?panel=`，恢复时有白名单，未知值回到 `outline`。

改为五个：**单元 / 资料 / 摸底 / 练习 / 验证**，所有课程一致；化学的「考核」并入「验证」。页签沿用 `.cl-course-tabs` 样式并扩充白名单。

任务、诊断、报告三个旧工作区目前都假设自己独占页面（各自的 `<main>`、各自注册导航、直接改写 URL），不能原样嵌入。分两步：

1. 页签内先放本课程的摘要和入口：摸底结果、到期复测、最近报告，点开进入旧工作区并带上课程上下文和返回路径。
2. 逐个给旧工作区加「嵌入」模式（不注册导航、不改写宿主 URL），再真正搬进页签。报告的会话列表最容易，先做；`AssessmentStudio` 最重（531 行，多处 `router.push`），最后做。

### 4.3 学习者与陪伴者

- 界面文字统一用「学习者」。「孩子」「学生」「家长」只在确有必要的设置页出现。
- 一个账号可以有自己的学习者档案，也可以作为陪伴者查看被授权的其他档案；底层仍是 parent/student 角色和现有授权关系。
- 档案上的「未成年」开关：已有的儿童档案默认打开，独立成人默认关闭。打开后的差别只在 AI 输出检查的严格程度和联网检索范围，不改变界面布局。
- 现状：学习者档案只有昵称、年级（1～9）、教材版本和单次时长，没有年龄或未成年字段，也没有修改档案的接口；独立成人不存档案（`studentId` 为空）。所以要新增一个可选字段和一个修改接口：字段缺省按「未成年」处理，没有档案的独立成人按成年处理。

## 5. 讲授层：向 HyperKnow 看齐的三件事

1. **阶段状态与逐句呈现**。现状是课堂插问每 1.2 秒轮询一次轮次状态，回答整段返回；模型调用走 Codex 结构化输出（一个完整 JSON 对象），传输层也整段缓冲，拿不到中间文字。所以分两步：第一步把任务已有的阶段字段暴露到轮次视图，worker 写入「读取课堂 / 组织讲解 / 检查输出」等阶段，回答通过检查后在前端逐句呈现并与旁白同步；第二步才是真正的逐字流式，需要改模型传输和输出格式，并处理全局响应封装（现在的拦截器会把流折叠成一次返回），单独立项，不在本轮。
2. **语音打断**。学习者开始说话或按住说话时，当前旁白立即暂停，回答结束后从断点继续。现有的 `pause()` 会连语音识别一起中止，`ask()` 又必须由表单事件触发，所以要拆出「只停旁白」的暂停和可直接调用的提问。第一版仍用浏览器内置识别；服务端没有任何语音识别，另列，不在本轮。
3. **输出检查全覆盖**。`inspectTeachingOutput` 现在只在两处调用（`ai.service.ts` 和 `classroom-turn-worker.service.ts`）。白板讲解、白板提问、课程生成、资料课程及其单元核查、助教教学、教学工具和旧的同步课堂提问接口都没有经过它，写入前都要补上；指导模型用的是自己的一套正则，并入同一入口。它目前只接受字符串、只拦「给学习者贴标签」和「对学习者下确定的原因结论」两类，没有严格程度参数：要加一个遍历嵌套结构收集可见文字的辅助函数（跳过 id、锚点、公式等字段），并为未成年档案增加更严格的一档。

## 6. 闭环的两个连接点

摸底结果和课程设计之间、课堂和验证之间，现在是断开的。

**连接点一：蓝图读取摸底结果。** 现状是课程生成只在「学习者有未完成评测」时拦一下，蓝图提示词里没有任何诊断或掌握度输入。改为：

- 学习者档案和学科都已知时，生成追问和蓝图前读取 `DiagnosticsService.profile()` 的知识点估计，把「稳固 / 不稳固 / 未知」的知识点名称摘要放进模型上下文，蓝图据此决定跳过、复习或补前置。
- 自由主题没有对应知识点时，用课程自己的摸底（见下）和追问回答。
- 摘要随蓝图一起保存，学习者能看到「这份蓝图参考了哪些已有结果」。
- 注意：`generationFingerprint` 会对 `craft` 对象整体取指纹，新增字段只写入新建的课程，不回填进行中的课程，否则断点续写会被拒绝。

**连接点二：AI 课程产生估计级证据。** 见第 3.3 节。AI 课程的「摸底」页签是按蓝图目标生成的开课前短测（估计级）；教材同步课程的「摸底」沿用化学课程的检查点模式（正式级），从化学推广到其他学科。

## 7. 账号与安全

- **邀请制注册**。现状 `register()` 没有任何开关，公网域名上任何人都能注册成 parent。改为由配置决定：生产环境默认需要邀请码，没有配置邀请码时注册关闭；本地开发和测试默认开放（约 200 个测试和脚本文件都通过 HTTP 注册，默认值不能影响它们）。邀请码第一版放在配置里，不新增集合；注册请求的校验是严格模式，需要同时加上邀请码字段，注册页加输入框。
- 生产环境拒绝默认的 `JWT_SECRET`。
- 11 月 5 日的五个安全提交（学生代码运行默认关闭、模型子进程隔离等）仍未推送、未发布，线上运行的还是 11 月 4 日的构建。它们随本轮第一次发布一起上线。
