# 长PDF处理、页级续跑与原件生命周期

2026-10-24，先归档后实施的增量规格，接续[规格103](103-long-source-course-compilation.md)和[完整主方案](92-experience-and-content-master-plan.md)。目前处于独立分支的分阶段交付，不能当作本规格全部完成或生产已交付。

## 1. 起点与目标

长资料课程第一增量`730abf8`已支持多资料合计120页/180000字符/180块/24课的编排，保留独立检查点及来源范围。单份工作台PDF仍走10MB内存上传、请求内初步解析和最多30页限制；结构处理虽然是后台任务，但没有页级结构检查点。已去掉静默正文/行数截断，保留完整提取结果；真实原件和新处理页图进入备份。历史页图未登记摘要，删除资料记录后PDF/TXT物理原件仍需回收。

本增量让使用者可导入一章或一本较长PDF，知道原件是否已收齐、哪些页真正处理、哪些页还不能使用；服务重启后只续缺失页。课程编排仍选择明确范围，处理完一本PDF不代表整本已生成课程或通过内容审核。

## 2. 用户流程

1. 选PDF后先显示文件名、大小和本次处理预算。小文件沿用旧上传兼容入口，大文件走受控分块；上传中断重新选同一文件可继续，不把尚未收到的字节算作已保存。
2. 服务端完成原件字节核对后返回持久资料ID和处理任务。上传完成与正文可用分开显示；原件可在鉴权后下载，原页/正文处理状态逐页可见。
3. 显示真实已处理页数、OCR页数、识别失败页和结构待核对页。前台离开、刷新或换设备读取同一任务，不依赖浏览器内定时器重建进度。
4. 已完整处理的页可对照原页；尚未处理、无法识别和失效页不能被默认为可选正文。第一实现以处理任务完整发布为选课门槛，避免边处理边生成造成材料版本漂移；按页提前选课如需开放，必须另外设计不可变页版本。
5. 取消先显示请求停止；已保存原件和页级检查点保留，重试沿原件与算法版本继续。新模型结构核对产生候选版本，不覆写旧课堂来源。
6. 可把已处理资料中的指定页选成不同课程包。编排预检列明未识别页与超出本次课程范围的页，不用“文件共120页”代替“可读正文120页”。

## 3. 文件上传与范围

首批工作台后台处理预算为120页、50MiB；这是单次运行预算，资料存储和外部资产归档不因此删除或裁剪。更大文件必须明确告诉用户如何拆分处理范围，禁止静默读前120页。提高预算要有实际压力、取消与恢复证据，不能只修改常量。

新增资料上传会话：文件名、媒体类型、声明字节、档案/学科、请求键、分块大小、已收到块摘要与有效期。普通学习身份只操作自己可访问的资料作用域；不借用管理员题卷上传权限。复用现有文件分块及路径/哈希基础设施时，先抽取存储与校验层，不把管理员控制器直接开放给学生。

固定分块不超过4MiB，块索引/字节数/摘要不可变；相同请求键/相同元数据重放原会话，改元数据拒绝。完成命令逐块读入流式哈希，验证PDF签名及完整字节数后登记原件。HTTP JSON仍512KiB有界；大PDF不得走单个JSON/base64或无限内存multipart。

页数预检不在HTTP中完整提取全书正文；在后台受控子进程读取页数/加密状态。上传/元数据检查失败与OCR失败分别保留准确状态。入库前的暂存文件也纳入保守清理，崩溃不能把暂存当成已完成原件。

## 4. 页级处理检查点

`pdf_structure`升级处理器版本，缓存键包含原件SHA、处理算法及页码。每页检查点保存完整原文、行、结构候选、方法/置信/警告、原页图摘要/大小/尺寸及处理时间。JSON与图片分别使用临时文件后原子改名；恢复必须同时验证版本、源摘要、页码、JSON完整性与图片摘要。

损坏检查点不能标成已处理；可明确重新处理该页并保留错误记录。进度来自真实检查点，不能用旧任务页计数直接累加。处理预算控制子进程总时长、单页像素及结果大小，超限失败必须指明实际已保存范围，原件和已完成页不丢失。

课程仍读取冻结材料版本。结构任务最终事务重查资料、当前授权、原件身份和租约后发布；取消、撤权、删除和旧worker均不得发布。任务恢复保留原件与算法版本；升级处理器时不把旧候选冒充同一版本的成功检查点。

## 5. 原文与模型结构候选

完整提取原文继续作为来源层。模型段落、表格和公式分别保留候选与实际核对页，不替换原始文字；不能定位原文的结构保留页级回看。跨页表格、公式、双栏、扫描/混合文字、旋转与不可读页须有单独状态。

现有模型只看少数页时，界面显示确切页码及未看范围；未被模型看过的页不能获得模型已核对标记。选原文和确认结构的范围、时间与材料版本应可追溯。表格/公式恢复正确性仍需真实原页对照，不由模型自评变成教师批准。

## 6. 原件引用、备份与回收

统一维护上传原件、页图、检查点和材料记录的引用。新页图已有摘要；旧资料需在实际存在且字节可核验时回填摘要，缺失页明确缺失，不猜哈希或宣称完成。原件相同但作用域不同可共享内容寻址字节，授权仍按各自资料记录。

回收以数据库当前引用、运行中的处理租约、待恢复任务及保留宽限期共同判断。删除一个家庭的资料不能删掉另一家庭仍引用的原件；课程冻结原文是否仍需要原件下载由课程依赖明确保留。先实现预览/审计，再由持久任务保守回收；暂存目录与正式原件分开规则。

SQLite/PG备份必须收齐上传原件、所有已登记页图与可恢复检查点；恢复到空目录后实际继续处理。删除账本应用后再计算无引用字节，旧备份中的孤立文件也按规则回收；只删除数据库行不称物理擦除完成。既有离线备份和用户已下载副本仍由其持有者管理。

## 7. 接口与页面职责

上传会话的创建、状态、块写入、完成、取消均带明确作用域和版本。材料进度接口只返回页状态和计数，指定页再读取正文/图片；资料列表避免返回全书全部正文。全书选择使用页清单/区间，服务端解析真实页号和当前版本。

现有30页小PDF入口保留兼容；新前端统一走可靠的后台路径。长页清单按页段展开，键盘可到达未完成/失败页和当前页。手机优先显示上传/处理下一步与失败恢复，不把数百页文字一次铺满页面。原件下载、页图和正文均继续鉴权，不能产生可绕过撤权的永久公开URL。

## 8. 验证与交付门槛

验证真实超过30页和10MiB的匿名原件、120页压力、扫描/混合/空白页、加密/损坏PDF、超预算和极密文字；所有页号、尾部文字及实际处理页数可核查。分块上传覆盖中断重选、同键冲突、乱序/重复块、完成回执丢失、哈希不符与撤权。

SQLite和实际PG覆盖页级中断续跑、进程重启、取消/删除/旧worker栅栏、算法变化、备份恢复继续处理和共同引用原件保留。删除/暂存回收使用隔离数据，校验物理目标确切归属，不操作生产家庭资料做验收。

浏览器覆盖上传、离开恢复、页级状态、未识别页反馈、原页定位、长来源编排与最终课堂；390/768/1440宽度、键盘、长清单滚动和失败焦点均检查。真实OCR/模型样本另外记录耗时、实际页范围及内容错误，不能用替身流程代替识别正确性。

交付顺序：规格归档提交 → 上传持久会话与范围校验 → 页级完整检查点 → 界面/按页读取 → 恢复与版本 → 原件引用和保守回收 → 双库/浏览器/真实内容验证 → 归档、CI及守护部署。各阶段均不表示完整产品总目标完成。


## 9. 回收实现前的并发细化

以下是回收阶段的实施约定，仍待编码与验证。不能仅在删除前查询一次“没有引用”就删除共享SHA原件：另一个账号可能在查询后完成同一原件上传，旧处理进程也可能继续写入页图。

新增按SHA寻址的资产状态记录，回收先在领域事务内同时检查材料、冻结课程、未结束上传和处理任务引用，写入deleting状态及当前回收任务身份；上传和旧兼容导入在注册原件前必须读取该状态，正在回收时拒绝写入，提示重新读取状态。完成回收后保留递增版本的available记录，避免“空记录→删除中→空记录”的变化被并发请求当作从未发生。

写入方还必须在取得文件租约后另读最新资产generation，再与本次请求捕获的版本比较。否则一个旧请求可能在整轮回收已结束、purge标记已释放之后才开始写字节；即使最后数据库提交失败，也会重新留下私人原件。最新版本不一致时应在写入前拒绝；首次登记允许“仍未有记录”，回收完成后必须保留递增记录，不能把它删除成空白。

文件侧使用可核查的处理租约标记和回收标记。处理器先登记自己的进程标记，再确认没有回收标记，之后才读原件和写缓存；回收器先占用回收标记，再检查仍在运行的处理租约。有活进程、无法判断的租约或未知文件时保守保留并报告pending，不将其计入已擦除。处理子进程退出后释放标记；回收器只删除自己取得的标记，旧租约不能覆盖新回收任务。

上传分块按唯一上传ID管理。取消/过期/删除后保留不可复用的写入撤销标记，写入方登记短期写租约后再次检查该标记；回收等待已开始的写入结束，防止删除目录后旧请求重新创建有私人字节的孤立目录。恢复到空目录时应用删除账本后重新计算引用和撤销标记；不把旧快照中已经被撤回的上传恢复为可写。

首轮先提供只读审计，列出当前引用、可回收、仍在运行、宽限期内和无法确认的对象；随后接入持久回收任务及定期保守扫描。所有目标必须属于受控studio-materials/studio-uploads目录，路径和文件命名逐项校验；未知文件、链接和共享引用不能递归删掉。原始资料、页图、完整检查点、暂存分块和恢复删除账本分别验收。该阶段完成前，第一增量的元数据删除不能称为物理原件擦除完成。

## 10. 第一增量开发状态

开发位于独立工作树，生产守护版未切换。已接入4MiB分块、50MiB完整SHA核对、上传恢复、120页结构检查点、逐页租约栅栏、取消/重试、原文按需读取与两处上传界面；原有30页同步接口继续兼容。目录只发页概要，按页读取验证材料版本；OCR/模型候选不覆盖原文，模型实际核对页码单独保留。

实际超过10MiB的120页PDF、进程/数据库重开、取消后备份到空目录继续缺失页、学习码权限与监护撤权等已有隔离SQLite验证。浏览器覆盖31页分块中断、丢失完成回执、批量选页、40页取消续跑、原PDF工作台41页切换及旧长文字流程。第一增量`3207221`的应用、浏览器、PG三组远端CI通过，见[基础CI](../evidence/2026-10-24/long-pdf-foundation-ci.json)。新上传链路的实际PG补验见下节，不能混用旧PG套件来证明本链路。历史页图回填、并发共享原件回收、删除账本文件清理和最终完整回归仍待；**本规格仍未全部完成，也未合入生产主线**。

## 11. 只读引用与文件审计、实际PG恢复

回收第一步已提供`npm run materials:audit -- --data-dir <独立数据目录>`，默认核验已登记文件的SHA和字节数。SQLite使用只读事务；PG通过`--connection-env <连接变量名>`读取可重复读的只读快照，密码不放命令行。可用`--output <资料目录外的新JSON路径>`存结果，拒绝覆盖已有证据。报告不包含课程正文、文件标题、家庭姓名和原始账号标识。

审计仅扫描`studio-materials`和`studio-uploads`；未知目录、符号链接和Windows目录联接不进入。原件、版本页图、完整JSON检查点和上传块分别识别。材料记录、冻结课程、活跃处理任务和未过期上传共同保护同一SHA；取消请求中的任务仍属活跃。只剩冻结PDF引用而原材料记录已消失时，仍核对原件是否实际存在。登记缺失、损坏、冲突、非法引用或未知路径均使审计不完整，可回收候选全部降为待核查。宽限期默认24小时。

`referenced/active/grace/eligible/unknown`是某次快照的只读分类。eligible不能直接用于删文件；实际删除仍必须由事务后持久worker组合使用资产generation、文件/子进程租约及上传撤销标记。基础实现进度见下节，当前不提供删除命令，也不把审计通过解释为物理擦除已完成。

新上传专项增加真实PG模式，核验数据库名和专用角色后创建两个临时数据库。实际跑完>10MiB/120页、数据库重开、取消于已登记第2页、原生`pg_dump/pg_restore`到空库与空文件目录、只续缺失页、监护撤权及授权恢复，并对真实保存的原件/页图/检查点执行只读审计。SQLite13项相关回归、PG6项上传专项和7项审计行为测试通过；[专项收据](../evidence/2026-10-24/long-pdf-audit-acceptance.json)记录具体时点与范围。家庭资料归档也改为流式核验原件后交由tar流读取，避免为50MiB原件额外整份读入内存。

下一阶段继续第9节的并发回收实现；旧页图完整性回填、恢复删除账本后的物理清理、完整交付回归与守护部署仍保留未完成。

## 12. 写入与处理租约基础（尚未接通物理回收）

在只读审计之后接入全局技术集合`studioMaterialAssets`：按SHA保存available/deleting、generation和更新时间，回收版本记录不随家庭资料关系删除。新分块原件注册、旧PDF兼容入口及TXT文件导入都读取同一身份；取得原件文件租约后另读最新版本，不一致就在写字节之前拒绝。第一次尚未提交的登记可确认“仍无历史记录”，但已有回收版本不能退回空白。

文件协调目录为`studio-materials/control/<sha>`和`studio-uploads/control/<upload-id>`，与实际原件、缓存、分块目录分开。Node写入/组装和处理父进程先写PID/nonce租约，再检查purge或上传revoked标记；finally只释放自己持有的租约。Python在读取原件/创建缓存前登记自己的PID，因此父进程异常终止而Python仍活着时，不会只剩一个已经死亡的父PID供回收器判断。正常退出和异常都会释放自己的标记；强制进程退出保留可核查标记。

审计识别这些控制目录。实际存活的进程或purge保护整组文件；损坏/无法确认的标记保留为unknown并使清单不完整，死进程标记仍保留待回收器核对。PID被别的进程复用时保守视为活跃，不凭年龄直接移除。上传永久撤销标记的工具已验证：分块目录清空后，迟到写入仍会被挡住；它将在后续已提交的回收任务中调用，不提前在可能回滚的HTTP取消事务里写撤销标记。

自动化分别验证文件互斥次序、实际进程退出、Windows联接、上传撤销、独立存储实例的版本冲突，以及完成一整轮回收版本变化后的旧请求确实没有写回原件。最后一项在SQLite和实际PG分别运行；Python另以实际PDF页检查点和强制子进程退出验证租约。SQLite组合22项、PG组合11项、只读审计8项、Python租约3项与原检查点2项通过。结果及最初测试中未模拟真实登记写入的错误断言保留于[文件租约收据](../evidence/2026-10-24/long-pdf-write-fences-acceptance.json)。

该基础提交只提供回收所需的租约，物理worker进展见第15节。不能只因文件租约测试通过就把第9节整个回收能力标完成。

## 13. 持久回收worker实施顺序

本节在worker编码前归档。任务按source SHA或唯一upload ID分开；隐私删除、上传取消、成功完成后的分块回收和过期清理在对应领域事务中只排持久任务，HTTP不撤销文件写入权，也不删除字节。账号已删除不阻止内部清理任务运行。删除材料和课程来源时同时排相关SHA，未过期上传和仍保留的冻结课程继续保护原件。

source任务先在事务中核对所有材料、冻结来源、活跃上传和资产状态，再持任务检查点栅栏写deleting、递增generation及本次任务/回收身份。已有其他有效回收任务时等待；原任务已失败或取消时，新任务可接手同一回收版本，但文件侧仍必须另取互斥。上传任务只在上传已取消、已完成、已过期或记录确已删除后创建永久revoked标记；活跃写租约结束前不清空分块。

purge标记保存本次持有者PID/nonce、key、generation和回收身份，用独占创建取得。已有持有者仍存活、PID复用、标记损坏或无法核对时保留pending；只有确切死亡且内容身份可核查的旧标记才可接管。持有purge后重新查所有文件租约与活跃处理任务，未知或活跃的一律等待，不能用数据库任务超时推定Python已退出。

先完整列出该SHA或upload ID的受控文件，再动手逐项删除。只允许原件、已知版本页图/检查点、算法产生的受控暂存名和分块名；链接、未知文件及未知子目录使本对象pending。逐个unlink并只rmdir已知的空目录，不递归删除。每次删除前核对任务租约及当前资产回收身份。组装暂存名补SHA，后续崩溃暂存可定位到源；旧无SHA未知暂存继续待人工核查，不误归到某家庭。

删除完成后，在deleting仍生效时释放自己持有的purge标记，之后再以任务完成栅栏发布available和再次递增generation。这样最终状态不会成功但遗留自己的阻断标记；中断于二者之间时仍是deleting，可安全续跑。丢失任务租约的旧worker不得在释放标记后再删文件。取消、权限变化、文件晚到及重复回收均通过这套顺序处理。

新增专用于维护任务的可恢复等待：等待不消耗普通失败次数，保存原因和下次可运行时间；崩溃耗尽或外部取消的任务由定期扫描重新排队，避免原件永远卡在deleting。周期扫描也处理已过期上传、成功后遗留分块和有资产登记但已无引用的来源，保留24小时一般宽限；明确隐私删除可立即排队，仍必须尊重共享引用和文件租约。
